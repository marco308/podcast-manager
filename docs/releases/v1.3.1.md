A small release for anyone who runs it: structured logs, a Prometheus endpoint, and deploys pinned to the exact image they were tested with.

## Highlights

- **Logs you can query.** Every record is one line on stdout, JSON in production and plain text when `DEBUG` is on (override with `LOG_FORMAT=json|text`). There are three named loggers:
  - `podcast_manager.http`: one line per request, with the route template rather than the raw path, so no query strings;
  - `podcast_manager.events`: one line per job run, with its outcome;
  - `podcast_manager.error`: unhandled exceptions with their traceback.

  Successful health-check and scrape polls are counted but not logged.
- **Request ids.** Every request gets an id. It honours an inbound `X-Request-ID`, echoes the id back in the response, and includes it in any 500 error body, so an error someone reports can be matched to its traceback.
- **`GET /metrics` for Prometheus**, guarded by a bearer token. Without `METRICS_TOKEN` set, it answers 404 as if it didn't exist. It reports:
  - requests and latency, by route template;
  - job runs by outcome, with the time of each job's last run;
  - Spotify API calls by status.
- **Deploys pinned by digest.** `deploy.sh` resolves each published image's digest before touching a service and deploys `<image>:<sha>@sha256:…`, so every node runs exactly the build that was tested.
- **Housekeeping.**
  - A `Makefile` (`make help`) for the everyday commands.
  - Backend dependencies now live in `backend/pyproject.toml`; for development, use `pip install ".[dev]"` instead of the requirements files.
- **iOS build 14** (TestFlight, and the version now in App Review): "Try the demo" is a full-width button on the sign-in screen, with a line saying no server or account is needed.

## Upgrading

- **No migrations and no required config changes.** Pull the new images and restart (`IMAGE_TAG=1.3.1`).
- **Optional:**
  - `METRICS_TOKEN` turns on `/metrics`. Set it as an environment variable, through `METRICS_TOKEN_FILE`, or as a mounted `/run/secrets/metrics_token`.
  - `LOG_FORMAT` overrides the log format.
  - Both are in `backend/.env.example`.
- **If you ship logs somewhere that expects the old plain-text format,** set `LOG_FORMAT=text`.
- **Building the backend yourself:** the Dockerfile installs from `pyproject.toml`; `requirements.txt` and `requirements-dev.txt` are gone.
