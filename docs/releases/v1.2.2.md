A security patch: the iOS sign-in is tied to the app that started it, and the backend is hardened against rate limits and silently changing base images.

## Highlights

- **iOS sign-in code bound to the app (PKCE).** The iOS login ends with a single-use code in a `podcastmanager://` callback URL. Until now anything that saw that URL within its two minutes could trade the code for the session. The app now sends a challenge when it starts the login and the backend only redeems the code for the matching verifier, which never leaves the app. This takes effect with an iOS build that includes the change; older builds keep working as before.
- **Requests no longer wait minutes on a Spotify rate limit.** A manual sync or playlist run used to sleep up to five minutes on a Spotify 429 while holding the lock other work waits on. It now gives up after 10 seconds and reports the rate limit; the scheduled jobs still wait as before.
- **One Spotify rate budget for the whole server.** A manual sync and a scheduled job running together now pace against the same window instead of each running at full speed.
- **Base images pinned by digest.** The Python, Node and nginx base images carry a digest next to their tag, so a rebuild can't pick up a re-pushed tag unannounced.
- **Dependency updates** since 1.2.1 (Dependabot and two advisories in dev-only frontend tooling, minimatch and zod): minor and patch bumps of FastAPI, SQLAlchemy, Pydantic, python-multipart and the frontend's npm packages.

## Upgrading

- No migrations and no config changes. Pull the new images and restart (`IMAGE_TAG=1.2.2`).
- Nobody needs to sign in again. To get the bound sign-in on iOS, update the app once a build with this change is available.
