Run history, and manual runs that no longer time out. Also: playlists that show when their last update failed, a sign-out instead of an error when stored credentials can't be read, and Python 3.15 under the hood.

## Highlights

- **Manual runs finish even when they take a while.** Run and Update All in the web app now start the rebuild on the server and follow it until it's done, so a large rebuild no longer ends in a network error after 30 seconds while the server keeps working. You get the same success, partial, skipped or error message as before. Installed iOS builds keep using the old way of running, which still works.
- **Run History.** Settings has a new table of recent runs: the daily rebuild, the library sync, played-episode cleanup and manual runs. Each row shows its status, when it started, how long it took, how many playlists failed and why.
- **Playlists say when their last update went wrong.** A playlist whose last build failed, or was written without some of its shows, carries a "Last update failed" or "Incomplete" tag on the dashboard, the playlist list and its page, with the reason on the page.
- **Signed out instead of an error when stored credentials can't be read.** If the server can no longer decrypt your stored Spotify tokens (for example after the encryption key changed), you're sent back to the login page instead of getting a 502 you can't fix by retrying.
- **Linking an existing Spotify playlist pushes the name.** A playlist linked to one of your Spotify playlists now renames it to match straight away instead of on the next change.
- **Smaller fixes.**
  - The Spotify playlist picker says when it only checked your first 1,000 playlists.
  - `PATCH /api/playlists/{id}` rejects `null` for a setting that can't be empty instead of silently ignoring it.
- **Python 3.15.** The backend image now runs on Python 3.15.

## iOS (TestFlight)

- **Build 13**, in TestFlight now: Settings shows the server's time zone next to the daily update times, and the time editor says the times are the server's. A server older than this release doesn't send the zone, and the times show as before.
- **Not in build 13:** Settings marking a failed or interrupted run with a warning instead of a checkmark, and the "Incomplete" / "Last update failed" labels on playlist rows. They need the next build.
- **Any build:** iOS keeps running manual updates the synchronous way, which this server still supports.

## Upgrading

- **One migration, `022_run_history`,** runs on its own when the container starts. It adds nullable columns for each playlist's last result and for a manual run's outcome; nothing to do.
- **No config changes, and nobody needs to sign in again.** Pull the new images and restart (`IMAGE_TAG=1.3.0`).
- **API clients:** a manual run (`POST /api/playlists/{id}/run`, `/api/playlists/run-all`) is unchanged unless the request sends `Prefer: respond-async`. Then it answers `202` with a `run_id` to poll at `GET /api/jobs/runs/{id}`. `GET /api/jobs/runs` lists recent runs.
